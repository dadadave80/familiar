## Recorded discrepancies (NEAR AI, 2026-11-13)

- **E2EE version.** docs.near.ai's E2EE guide documents `X-Encryption-Version: 2` with no associated data. `@nearai/inference-sdk` 0.3.0 and nearai/inference-proxy `docs/e2ee.md` (commit 724cf65) use v3, which binds the reply key and a field label into each field's AEAD associated data, and say clients must not downgrade. The live gateway accepted v3 for `z-ai/glm-5.3-flash`. Familiar uses the SDK's v3 encryption; its test TEE reproduces the inference-proxy Ed25519 v3 vector. The SDK also sends `X-Encrypt-All-Fields: true`; the relay forwards it.
- **Attestation key.** The installed NEAR AI Cloud skill and model-verification notes say model attestation reports require an API key. The current E2EE guide says the gateway attestation endpoint needs none, and keyless model reports returned 200 today. Familiar fetches them keyless from the browser. A future 401 makes the note broken; no relay attestation fallback exists.
- **Reasoning control.** `chat_template_kwargs.enable_thinking:false` did not stop GLM-5.3 Flash reasoning (two live notes broke at `max_tokens`). docs.near.ai's reasoning-models page names `thinking_token_budget` for this model; `0` produced content.
- **Signature URL.** The skill shows `/v1/signature/{id}?model=…&signing_algo=…`; the SDK and Familiar omit `model`, and the signature was found on the first try.
- **Model tier.** `/v1/models` has no explicit tier field (`owned_by:"nearai"`). The SDK's attestation criterion (`/v1/model/{id}`: `providerType:"vllm"`, `attestationSupported:true`) is what Familiar checks.
- **Brief vs repository.** The handoff said `.env.example` already had a `NEAR_AI_API_KEY` placeholder; it did not. The placeholder was added (empty).
